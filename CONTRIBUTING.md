# Contributing to JEETrack

Thanks for wanting to contribute — even though the production source is
private, there's still real ways to help.

## What you can contribute here

This repo (`jeetrack-docs`) covers documentation, guides, and
community-facing material. You can help with:

- Fixing typos, unclear wording, or outdated info in `docs/`
- Improving the FAQ with questions you had to figure out yourself
- Suggesting roadmap items or upvoting/discussing existing ones
- Filing well-written bug reports or feature requests
- Improving issue/PR templates

## What lives elsewhere

- **Engineering patterns / architecture** → [`jeetrack-showcase`](https://github.com/AmanxMishraDev/jeetrack-showcase).
  That repo takes generalized code snippets, but the production app itself
  isn't open for PRs since it's a live product handling payments and user
  data.
- **Bugs in the live app** → open an issue here using the Bug Report
  template, even though the fix will happen in the private repo.

## How to contribute a doc change

1. Fork this repo
2. Create a branch: `git checkout -b docs/short-description`
3. Make your change
4. Open a PR against `main` using the PR template
5. Describe *what* changed and *why* — small, focused PRs are easier to
   review and merge quickly

## Reporting bugs

Please use the **Bug Report** issue template and include:

- What you expected to happen
- What actually happened
- Steps to reproduce
- Browser/device, if relevant (JEETrack is a PWA — mobile vs desktop
  sometimes matters)
- Screenshots if it's a visual bug

## Suggesting features

Use the **Feature Request** template. A quick note on scope: JEETrack is
built and maintained solo, so features get prioritized against real
engineering time — a clear, well-scoped request (with the *problem* it
solves, not just the feature) has a much better shot at making the
[roadmap](ROADMAP.md).

## Code of Conduct

By participating, you agree to follow the [Code of Conduct](CODE_OF_CONDUCT.md).

## Questions?

Open a [Discussion](../../discussions) rather than an issue if it's not a
concrete bug or feature request.
